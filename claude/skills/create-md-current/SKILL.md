# セッション内容を MD に書き出す（create-md-current）

いま進行中の会話の中身を要約し、**カレントワーキングディレクトリ**に Markdown として保存する。
単なる発言ログではなく、**決定・理由・次の一歩**を後から読んで動ける形で残すのが目的。

## 大原則（厳守）

1. **捏造しない。** このセッションで実際に話した/決めた/作ったことだけを書く。話していない結論を足さない。
2. **出力先はカレントディレクトリ。** 別所の絶対パスに書かない。`pwd` のディレクトリに置く。
3. **既存ファイルを無確認で上書きしない。** 同名があれば末尾に `-2`,`-3`… か時刻を付けて衝突回避。特に編集中の curated な資料は潰さない。
4. **ログではなく要約。** 往復の逐語ではなく、決定事項・根拠・未解決点・次アクションを抽出する。
5. **動ける情報を残す。** 会話で出たファイルパス・コマンド・URL・トークン名を含める。**秘密情報（APIキー/トークンの値・パスワード）は値を絶対に書かない**（名前だけ）。

## 手順

### 1. ファイル名を決める
- 引数があればそれをファイル名/トピックに使う（例: 引数 `slack-bot` → `slack-bot.md`）。
- 無ければ `session-<今日の日付 YYYY-MM-DD>.md`。
- 同名が既にあれば `-2` 等を付ける。

### 2. セッションを棚卸しして抽出
- このセッションのテーマ/ゴール
- 決まったこと（決定事項）と、その**理由**
- 重要な事実・学び（調べて分かったこと・数値・制約。出典URLがあれば付ける）
- 作成/変更したファイル・コマンド・URL
- 未解決の論点 / 次の一歩

### 3. カレントディレクトリに Write
下記フォーマットで書き出す。

### 4. 報告
保存した**絶対パス**と一言サマリをユーザーに返す。

## 出力フォーマット

```markdown
# セッション記録: <テーマ>

- 日付: <YYYY-MM-DD>
- 場所: <cwd の絶対パス>

## このセッションでやったこと（要約）
- …

## 決定事項
- <決めたこと> — 理由: <なぜ>

## 重要な学び・事実
- …（数値・制約・調べた結果。出典URLがあれば付ける）

## 作成・変更したファイル / コマンド
- `path` — 何のため
- `command` — 何をする

## 未解決の論点 / 次の一歩
- [ ] …
```

## やってはいけないこと
- 話していない結論・数値をでっち上げる（最大のNG）。
- APIキー/トークン/パスワードの**値**を書き出す（名前だけにする）。
- カレント以外のディレクトリに書く。
- 既存の重要ファイルを無確認で上書きする。
- 逐語の全文ログをそのまま貼る（要約・構造化する）。
